Chamber 2Methods

The first word of every request is its method: what the client wants to do. The server recognizes seven methods by name. But it only knows how to do one thing, send a file, so it answers every method the same way.

Each method is sent for this page, one after another.
MethodWhat it means in HTTPServer response
GETGet a resource.—
POSTSend data for the server to process.—
PUTStore a resource at this path.—
DELETEDelete the resource.—
PATCHChange part of a resource.—
HEADLike GET, but only the headers.—
OPTIONSAsk which methods are allowed.—
BREWNot a real method. The server logs it as UNKNOWN.—

Look at the terminal where the server is running while you press the button. Each request shows up as Request Method: POST and so on, and BREW shows up as Request Method: UNKNOWN.

Why Are They All the Same?

parse_method() turns the first word into one of eight values, and main.c writes it to the log. Then it calls send_file() whatever the method is. The body sent with POST, PUT and PATCH is never read.

For HEAD, the server sends the whole file anyway. HTTP says a HEAD response has no body, so your browser throws those bytes away, and the table shows 0.

A complete server would save the body of a PUT, delete a file on DELETE, and answer OPTIONS with an Allow header. This one only reads files.

In the code src/http_request.c: parse_method(). The log line is written in src/main.c.
