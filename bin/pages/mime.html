Chamber 5Content Types

A browser can't tell a web page from a picture just by looking at the bytes. So the server labels every response with a Content-Type header. It decides the label from one thing only: the text after the last dot in the file name.

Five files, and the Content-Type the server sent for each
FileExtensionContent-Type received
/index.html.html or .htm—
/styles.css.css—
/samples/info.json.json—
/images/parchment.png.png—
/samples/notes.txtAnything else, like .txt—

Every Other File

Any other extension, or no extension at all, gets text/plain; charset=UTF-8. That includes .js, .svg and .gif files. In 1996 every homepage had animated GIFs; this server would label them as plain text, so the background images of this castle are PNG files instead.

The check is case-sensitive: PHOTO.PNG would be labelled as plain text too.

In the code src/file_handler.c: get_mimetype_for_file() reads the extension, and get_mime_string() in src/http_response.c turns it into the header value.
