Chamber 6Streaming a Large File

This picture of a knight is 2,056,264 bytes, but the server never loads it into memory all at once. It reads 4,096 bytes from disk, sends them, and reuses the same small buffer for the next piece, until the whole file is sent.

The Numbers

Content-Length2056264, sent before the first byte of the picture, so your browser knows when the picture is complete.
Pieces502 pieces of 4,096 bytes, and a last piece of 72 bytes.
send() calls1 for the status line and the headers, 503 for the picture.
MemoryOne 4,096-byte buffer, whatever the size of the file.

Try It

Waiting

Press the button to download the picture again.

If the Client Leaves Early

If you close this page while the picture is still downloading, the server's next send() fails. The server writes Error sending file: Broken pipe to its log, stops sending and moves on to the next client. Before a recent fix, this crashed the whole server.

In the code src/file_handler.c: get_file_size() measures the file for Content-Length, and stream_file_to_client() sends it in pieces of BUFFER_SIZE bytes.
