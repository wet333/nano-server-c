Chamber 4Headers

After the status line come the headers: one per line, each with a name, a colon and a value, and each line ends in \r\n. An empty line marks the end of the headers, and the body starts after it. This server sends the same headers with every response.

The headers of this page
HeaderValueWhat it tells the browser
Content-Typetext/html; charset=UTF-8What kind of file the body is. See Chamber 5.
Content-LengthThe size of the file in bytesHow many bytes of body to expect. See Chamber 6.
ConnectioncloseThe server closes the connection after this response.
ServerAWetServerV1.0The server's name, from SERVER_NAME in constants.h.
Server-Token987654321A custom header, sent with 200 responses only. It has no meaning: it shows that custom headers work.

Connection: close

HTTP/1.1 lets a browser send many requests over one connection. This server doesn't support that: it closes the connection after every response, so the browser has to open a new connection for each file. This page alone needed several: one for the page, one for the stylesheet and one for each background image.

The server also handles one client at a time. While it sends a large file to one client, the others wait in a short queue, set up by listen().

In the code src/http_response.c: get_response_size() writes the status line and the headers, and response_add_header() adds custom ones, up to 20.
